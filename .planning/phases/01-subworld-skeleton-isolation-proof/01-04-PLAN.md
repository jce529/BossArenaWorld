<objective>
Empirically prove, via a real King Slime kill inside the boss-arena subworld, that vanilla boss-downed flags do NOT propagate from the subworld back to the main world without an explicit carrier-item action. This is the founding premise (Pitfall 1 in prior research) that the entire Phase 3+ carrier-item architecture depends on -- if this test fails (flag DOES propagate, or does something unexpected), the architecture assumption must be re-opened before any further phases proceed.

Purpose: Validate SUBW-05 (zero placed content) and SUBW-06 (reliable enter/exit with inventory intact) empirically in a live game session, and prove the VERIFY-02 isolation premise this phase exists to establish.
Output: A completed manual test run with confirmed results (no code artifacts -- this plan is pure verification of Plans 01-03's work).
</objective>

  <what-built>
    Plans 01-03 built: a Subworld subclass generating a ~10,000-block-wide flat stone platform via a single custom GenPass (Subworlds/BossArenaSubworld.cs, Subworlds/FlatStonePlatformPass.cs); three debug chat commands to enter/exit the subworld and check the downed-flag value (Debug/SubworldDebugCommands.cs); and a generic biome-override infrastructure hook (Systems/BiomeOverridePlayer.cs, not exercised by this test since King Slime needs no biome override). This task verifies all of it works together in a live game session and proves the isolation premise.
  </what-built>
  <how-to-verify>
    On the disposable test world from Task 1, in singleplayer:

    1. Confirm baseline: type `/bossarena-checkflag` in chat. Confirm it prints `NPC.downedSlimeKing = False`. (A brand-new world should already have this false; this confirms the check-flag command itself works and establishes the pre-test baseline.)
    2. Type `/bossarena-enter`. Confirm:
       - The screen transitions into the boss-arena subworld (loading transition occurs).
       - You land on a walkable stone platform -- NOT falling indefinitely and NOT spawned entombed in stone (Pitfall 2 check).
       - Fly or walk a reasonable distance across the platform (using Creative/cheat items or god mode is fine for inspection purposes) and confirm you see ONLY stone platform tiles -- no NPCs, no structures, no ore veins, no biome-specific terrain of any kind (SUBW-05 visual check).
    3. Note your current inventory (e.g. screenshot or mentally note a few distinctive item stacks/counts).
    4. Summon King Slime for real: use a Slime Crown item (spawn one via `/give` equivalent, admin/creative menu, or vanilla means), or trigger natural Slime Rain if that's easier to set up. Either counts as "a real kill" per D-11.
    5. Fight and defeat King Slime inside the subworld. Confirm normal kill behavior (death animation, loot drop if any).
    6. Do NOT use any carrier item -- none exists yet (D-12). Do not manually toggle any flag. Just confirm the kill registered normally in-subworld.
    7. Type `/bossarena-exit`. Confirm:
       - You return to the main world (not stuck in a transition or crashed).
       - Your inventory matches what you noted in step 3 -- nothing lost, nothing duplicated (SUBW-06 check).
    8. Type `/bossarena-checkflag` again, now in the main world. Expected result: prints `NPC.downedSlimeKing = False`. This is the correct, expected outcome -- it proves the isolation premise (the kill happened in a world that was regenerated from scratch and never saved; exiting reloads the main world's own file, which never recorded the kill).
    9. If step 8 instead prints `True`, this is an unexpected finding that contradicts the architecture's foundational assumption -- do NOT proceed to Phase 2 planning; flag this result explicitly so the premise can be re-investigated.
  </how-to-verify>
  <verify>/bossarena-checkflag in the main world after the full round trip prints "NPC.downedSlimeKing = False"</verify>

    - Step 7 inventory after `/bossarena-exit` matches step 3's noted inventory exactly
    - Step 8 final check prints `NPC.downedSlimeKing = False` in the main world
  </acceptance_criteria>
