## hivemind-zonecorrupt-despawn-corruption-subworld — Hive Mind despawns instantly in a plain-stone arena because it has no Corruption biome tiles
- **Date:** 2026-08-13
- **Error patterns:** despawn, timeLeft, ZoneCorrupt, biome, Corruption, HiveMind, AI(), Sky Ore, downedHiveMind, double message, SceneMetrics, CorruptBiome, CanDrop
- **Root cause:** `CalamityMod.NPCs.HiveMind.HiveMind.AI()` re-caps `NPC.timeLeft` to ~60 ticks whenever its target-validity check fails, which includes `!player.ZoneCorrupt`. `Player.UpdateBiomes()` recomputes `ZoneCorrupt` every tick from `Main.SceneMetrics.EnoughTilesForCorruption` (needs a weighted sum >= 300 of nearby "evil" tiles, e.g. Ebonstone/CorruptGrass, each weight 1). `BossArenaSubworld`'s platform is plain Stone, so the count is always 0 and Hive Mind despawns almost immediately after spawn. Separately, `BossCoreDropRule.CanDrop` was hardcoded to `SubworldSystem.IsActive<BossArenaSubworld>()`, so any boss killed in a different arena subworld type would silently never drop its carrier item. A follow-up "double Sky Ore message" symptom (message appears once in-subworld, once again in main world) is NOT a bug — it is expected behavior of the carrier-item architecture: the real `ModNPC.OnKill()` (Calamity's own) always fires on a genuine kill even inside a throwaway subworld, but the in-subworld world-save writes to the subworld's own throwaway file path (`Main.ActiveWorldFileData`/`worldPathName` still point at the subworld until `SubworldSystem.LoadWorld()` repoints them back to main, which happens AFTER the exit flow's early `WorldFile.SaveWorld()` call), so the real main `.wld` never receives the in-subworld flag write and the carrier-item apply path runs for real exactly once against the actual main world.
- **Fix:** Added `Subworlds/CorruptionPlatformPass.cs` (full-width Ebonstone + CorruptGrass platform GenPass) and `Subworlds/BossArenaCorruptionSubworld.cs` (second arena Subworld reusing the OnEnter/OnExit vanilla-flag snapshot/restore guard from `isolation-premise-flag-persistence.md`). Added `Systems/BossArenaRoutingRegistry.cs` (boss-agnostic type registry + `IsAnyArenaActive()`) and rewired `Tiles/Test1Tile.cs`, `Systems/BossSummonPlayer.cs`, and `ItemDropRules/BossCoreDropRule.cs` to route/check through the registry instead of a hardcoded `BossArenaSubworld` type check. `Integrations/CalamityIntegration.cs` registers Hive Mind against the new corruption arena and gained a documentation comment explaining the double-message mechanism (no functional change needed there).
- **Files changed:** Subworlds/CorruptionPlatformPass.cs, Subworlds/BossArenaCorruptionSubworld.cs, Systems/BossArenaRoutingRegistry.cs, Tiles/Test1Tile.cs, Systems/BossSummonPlayer.cs, ItemDropRules/BossCoreDropRule.cs, Integrations/CalamityIntegration.cs
