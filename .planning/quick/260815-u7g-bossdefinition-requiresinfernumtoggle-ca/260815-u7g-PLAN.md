<objective>
A prior quick task (260815-to6) gated `CalamityIntegration.ForceInfernumModeActiveInArena()` (forces InfernumMode's per-world toggle active before spawning an arena boss -- see the Old Duke despawn-bug precedent) using `BossRegistry.TryGetKeyForNpc(...)` + `bossKey.StartsWith("calamity:")`. A code review flagged this as a naming-convention proxy for the real condition ("does this boss's AI actually depend on InfernumMode's toggle?") and found a concrete gap: `catalyst:astrageldon` (`Integrations/CatalystIntegration.cs`) is a CalamityMod-dependent CatalystMod addon boss, keyed `catalyst:` not `calamity:`, so it was silently excluded from the fix.

Replace the string-prefix heuristic with an explicit `RequiresInfernumToggle` flag on `BossDefinition`, set true only on the four Calamity boss registrations that genuinely need it (Providence, Profaned Guardians, Astrum Deus, Astrum Aureus). Astrageldon's actual InfernumMode dependency was investigated this session by decompiling `Libs/InfernumMode.dll` via `ilspycmd`: across all 2097 types in the assembly, there are zero references to "Astrageldon" or "Catalyst" anywhere -- InfernumMode has no AI override, hook, or type reference targeting CatalystMod's Astrageldon at all (unlike Providence/Profaned Guardians/Astrum Deus/Astrum Aureus, which are CalamityMod's own NPC types that InfernumMode explicitly reworks). This is a confirmed finding, not a guess: Astrageldon's `BossDefinition` correctly leaves `RequiresInfernumToggle` at its default `false`, documented in-code with the decompile evidence so the judgment call is traceable.

Purpose: Make "does this boss need InfernumMode's toggle forced active in-arena" an explicit, per-boss, self-documenting fact on each `BossDefinition` instead of an implicit guess inferred from a key-naming convention that has nothing to do with the actual condition -- closing the code-review gap and preventing the same silent-exclusion mistake for any future boss registration.
Output: `BossDefinition` gains a `RequiresInfernumToggle` field; `BossRegistry` gains a `TryGetDefinitionForNpc` accessor; `BossSummonPlayer.OnEnterWorld()` checks the flag instead of the string prefix; the four Calamity bosses that need it are flagged true, Astrageldon is explicitly and correctly left false.
</objective>

    }
