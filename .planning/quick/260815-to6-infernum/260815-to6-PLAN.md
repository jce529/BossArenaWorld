<objective>
`Systems/BossSummonPlayer.cs`'s `OnEnterWorld()` currently calls `CalamityIntegration.ForceInfernumModeActiveInArena()` for EVERY boss summon whenever `ModLoader.HasMod("InfernumMode")` is true, regardless of which mod's boss is being summoned -- so a Spirit-mod boss (or any future non-Calamity boss) would also trigger it unnecessarily. Gate the call so it only fires when the boss currently being summoned (`PendingBossNpcType`) is a Calamity-sourced boss.

Purpose: `ForceInfernumModeActiveInArena()` exists specifically to fix InfernumMode's own per-world toggle resetting inside the throwaway arena subworld, which only matters for Calamity bosses whose AI (or NoxusBoss's Old-Duke-hijack-style interactions) reads that toggle -- Providence, Profaned Guardians, Astrum Deus, Astrum Aureus. Calling it for a Spirit boss summon is a no-op in effect today but is semantically wrong and would silently mask a future bug if a non-Calamity mod ever adds its own conflicting `InfernumMode`-reading behavior.
Output: `BossSummonPlayer.OnEnterWorld()` reuses the existing `BossRegistry.TryGetKeyForNpc` boss-key lookup (namespaced `"modprefix:boss_name"` keys, e.g. `"calamity:providence"`, `"spirit:infernon"`, `"vanilla:king_slime"`) to check the pending boss's source mod before calling `ForceInfernumModeActiveInArena()`, instead of gating purely on whether InfernumMode is installed at all.
</objective>

    // Only Calamity-sourced bosses need InfernumMode's toggle forced active (Providence/

        && BossRegistry.TryGetKeyForNpc(PendingBossNpcType.Value, out string bossKey)
